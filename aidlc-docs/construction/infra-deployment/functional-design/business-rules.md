# Business Rules - Unit 3: Infrastructure Deployment

## BR-1: コンパートメント解決ルール

### BR-1.1: フォールバックチェーン
1. インスタンスメタデータAPI (`http://169.254.169.254/opc/v2/instance/`) から `compartmentId` を取得
2. 環境変数 `OCI_COMPARTMENT_ID` から取得
3. ユーザーに質問（最終手段）

### BR-1.2: 解決結果のキャッシュ
- 一度解決したコンパートメントIDはセッション中キャッシュする
- 同一セッション内で再度解決する必要はない

## BR-2: zip化ルール

### BR-2.1: 対象ファイル
- `generated/{project_name}/terraform/` 内の全ファイルを含める
- `.tf`, `.tfvars`, `.sh`（cloud-initスクリプト等）を対象
- `.terraform/` ディレクトリは除外

### BR-2.2: zip構造
- zipのルートにTerraformファイルを配置（サブディレクトリにネストしない）
- Resource Managerが直接読み取れる構造

## BR-3: Stack管理ルール

### BR-3.1: Stack命名
- display_name: `{project_name}-stack`
- description: "Auto-generated by OCI Demo Builder"

### BR-3.2: Stack設定
- terraform_version: "1.5.x"
- variables: terraform.tfvarsの値をStack variablesとして設定
- compartment_id: Phase 1で解決した値

### BR-3.3: 既存Stack検出
- 同名のStackが既に存在する場合、既存Stackを更新（zipを再アップロード）
- 新規Stackの重複作成を防止

## BR-4: Job実行ルール

### BR-4.1: ポーリング
- 間隔: 30秒
- タイムアウト: 60分（3600秒）
- ポーリング中はJobのlifecycle_stateを確認

### BR-4.2: lifecycle_state判定
| State | Action |
|---|---|
| ACCEPTED | 待機継続 |
| IN_PROGRESS | 待機継続 |
| SUCCEEDED | 成功、次のステップへ |
| FAILED | エラーハンドリング |
| CANCELED | エラーとして報告 |

### BR-4.3: Plan→Apply順序
- Plan Jobが SUCCEEDED の場合のみ Apply Jobを実行
- Plan失敗時はApplyを実行しない

## BR-5: エラーハンドリングルール

### BR-5.1: Plan失敗時
- Jobログを取得 (`oci resource-manager job get-job-logs`)
- エラー内容をClaude Codeが分析
- 修正可能なTerraformエラー（構文エラー、変数不足等）の場合:
  - Terraformコードを修正
  - zipを再作成
  - Stackを更新
  - Plan再実行（最大2回リトライ）
- 修正不能なエラーの場合: ユーザーに報告

### BR-5.2: Apply失敗時
- Jobログを取得 (`oci resource-manager job get-job-logs`)
- エラー内容をClaude Codeが分析
- 修正可能なエラー（リソース制限、パラメータ不正、依存関係エラー等）の場合:
  - Terraformコードを修正
  - zipを再作成
  - Stackを更新
  - Plan再実行 → Apply再実行（最大2回リトライ）
- 修正不能なエラー（権限不足、サービス制限等）の場合: ユーザーに報告
- 部分的に作成されたリソースはTerraform stateが管理しているため、修正後のApplyで差分適用される

### BR-5.3: タイムアウト時
- 現在のJob状態を報告
- Jobは継続実行中の可能性があるため、キャンセルはユーザー判断

## BR-6: 出力ルール

### BR-6.1: stack_outputs.json
- Terraform outputsのkey-valueをそのままJSONとして保存
- sensitive値もJSON内に含める（社内ツールのため）
- ファイルパス: `generated/{project_name}/stack_outputs.json`

### BR-6.2: Stack情報の記録
- Stack OCID を stack_outputs.json に `_stack_id` キーで追加
- Apply Job OCID を `_apply_job_id` キーで追加
- ユーザーがOCI ConsoleからStack管理するための情報
