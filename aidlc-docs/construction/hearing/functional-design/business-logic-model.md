# Business Logic Model - Unit 1: Hearing

## Overview

Hearing Skillは3段階のフローで動作する：
1. **要望解析**: ユーザーの自然言語要望を解析し、該当する質問カテゴリを特定
2. **質問生成**: 基本カテゴリ（必須質問）+ 動的追加質問をMarkdownファイルに出力
3. **回答処理**: 回答収集 → 矛盾検出 → 追加質問（最大3ラウンド）→ 構造化出力

## フロー詳細

```
User Request (自然言語)
      |
      v
[Phase 1: 要望解析]
      | カテゴリ特定
      | 必須質問の選定
      v
[Phase 2: 質問生成]
      | 基本カテゴリ質問 (事前定義)
      | + 動的追加質問 (Claude Code生成)
      | -> hearing/questions.md
      v
[Phase 3: 回答収集]  <--+
      | [Answer]:タグ読み取り  |
      v                      |
[Phase 4: 矛盾検出]         |
      | 矛盾あり? ---------->+ (追加質問ファイル生成)
      | (最大3ラウンド)       | hearing/clarification-N.md
      |                      |
      | 矛盾なし or 3ラウンド到達
      v
[Phase 5: 構造化出力]
      | hearing/result.json
      v
Complete
```

## Phase 1: 要望解析

### 入力
- ユーザーの自然言語テキスト（例: 「Eコマースのデモ環境を作って」）

### 処理
- Claude Codeが要望テキストを解析
- 以下のカテゴリのうち該当するものを特定:
  - プロジェクト基本情報
  - アプリケーション種別
  - インフラ構成
  - データベース要件
  - ネットワーク構成
  - スケーリング要件
  - 追加サービス
- 要望から明確に読み取れる情報は質問から除外（不要な質問を減らす）

### 出力
- 該当カテゴリリスト
- 要望から抽出済みの情報（質問不要な項目）

## Phase 2: 質問生成

### 基本カテゴリ質問（事前定義テンプレート）

各カテゴリに対して事前定義された質問テンプレートを持つ。形式はAI-DLC方式（選択肢+[Answer]:タグ）。

**カテゴリ一覧と必須質問:**

1. **プロジェクト基本情報**（常に必須）
   - プロジェクト名
   - 用途/目的の詳細

2. **アプリケーション種別**（常に必須）
   - アプリケーションタイプ（Web/API/バッチ等）
   - プログラミング言語/フレームワーク
   - コンテナ化方式

3. **インフラ構成**（常に必須）
   - コンピュート種別（OKE/Container Instances/Compute/Functions）
   - コンピュートの新規作成 or 既存利用
   - サイジング（CPU/メモリ）

4. **データベース要件**（アプリ種別に応じて）
   - DB種別（ATP/MySQL/NoSQL/なし）
   - サイジング

5. **ネットワーク構成**（インフラ構成に応じて）
   - VCN新規作成 or 既存利用
   - パブリック/プライベートアクセス
   - ロードバランサー要否

6. **追加サービス**（要望に応じて動的判断）
   - Object Storage
   - Streaming/Queue
   - API Gateway
   - その他

### 動的追加質問

Claude Codeが要望の内容に応じて、基本カテゴリでカバーされない質問を動的に生成する。
- ビジネスロジックの詳細
- 外部連携要件
- デモ用のサンプルデータ要件
- UI/UXの要件
- etc.

### 出力
- `hearing/questions.md` — AI-DLC形式のMarkdownファイル

## Phase 3: 回答収集

### 処理
- ユーザーが `hearing/questions.md` の各 [Answer]: タグに回答を記入
- ユーザーが完了を通知
- Skill が回答ファイルを読み取り、全 [Answer]: タグの回答を抽出
- 未回答の質問がある場合はユーザーに通知

## Phase 4: 矛盾検出

### 検出ルール
- **スコープ矛盾**: 小規模と言いながら大量のリソースを要求
- **技術矛盾**: サーバーレスなのにpersistent volumeを要求
- **構成矛盾**: プライベートサブネットなのにパブリックIPを要求
- **リソース矛盾**: OKEクラスター新規作成だがシェイプが未指定

### 追加質問フロー
- 矛盾検出時: `hearing/clarification-{round}.md` を生成
- ラウンド番号: 1, 2（最大2回の追加質問 = 合計3ラウンド）
- 3ラウンド到達時: 残存矛盾を `hearing/result.json` の warnings フィールドに記録

## Phase 5: 構造化出力

### 出力
- `hearing/result.json` — 後続ユニットが参照する構造化データ
